# Session Backup

Point-in-time export of all local agent session history, redacted of credentials.

Generated by `tools/export.py`, validated by `tools/verify.py`.

## What is here

| File | Contents |
|---|---|
| `hermes-sessions.jsonl` | 12 session records from `~/.hermes/state.db` |
| `hermes-messages.jsonl` | 4555 messages (content, tool calls, reasoning) |
| `opencode-sessions.jsonl` | 4 session records from `~/.local/share/opencode/opencode.db` |
| `opencode-messages.jsonl` | 1486 message records |
| `opencode-parts.jsonl` | 5492 message part records |
| `MANIFEST.json` | Counts, source paths, redaction summary |
| `SECRETS-ROTATE.json` | Fingerprints of every secret found — **rotate these** |

One JSON object per line, so files stay diffable and greppable across backups.

## Redaction

Live credentials were found embedded in conversation history and **have been
replaced**, not merely ignored. Each secret became a placeholder of the form:

```
[PRIVATE_KEY_REDACTED:33ea101d]
```

The suffix is the first 8 hex chars of the SHA-256 of the original value. It is
a one-way fingerprint: enough to tell whether two occurrences are the same
credential and to correlate against `SECRETS-ROTATE.json`, not enough to recover
the value.

This backup caught 30 distinct secrets across 108 occurrences — private keys, AWS
keys, OpenAI/Anthropic keys, a GitHub PAT, Slack tokens, JWTs. **Git history is
permanent, so these must be treated as exposed regardless of the repo being
private. See `SECRETS-ROTATE.json` and rotate them.**

## Deliberately excluded

Never copied, and blocked by `.gitignore`:

- `~/.hermes/auth.json` — provider access/refresh/agent keys
- `~/.bde-daemon/secret.bin` — daemon secret
- Raw `*.db` / `*.db-wal` / `*.db-shm` — binary, non-diffable, contain the above
- Model/provider caches, cookies, keys, `__pycache__`

This means the backup is **not a byte-exact restore**. It preserves conversation
content and structure, not live credentials or FTS indexes. If a faithful
restore is ever needed, copy the `.db` files directly to disk — never to git.

## Regenerating

```sh
python3 tools/export.py /path/to/output
python3 tools/verify.py /path/to/output   # exits non-zero if any secret survives
```

`verify.py` is a gate, not a formality. It caught three real leaks on the first
pass — a truncated PKCS#8 key body (`MII...`) and two bare `BEGIN PRIVATE KEY`
headers that the block-matching redactor had missed.

## Restoring

```sh
sqlite3 restored.db "INSERT INTO ... "   # or:
jq -c . hermes-sessions.jsonl            # per-line JSON
```
